## Obligation resolution

Only the first two and `true` are needed here. They validate values, not occurrence truth. T1 event checks additionally use the existing named criteria `attributed-bound-record/0.1` and `same-predicate-subject-scope-time/0.1` in [evaluateClaim.ts](../../packages/guard-core/src/mesr/repaired/evaluateClaim.ts).

## Exact private serialization

All objects below are JSON; field names are exact. This is a document specification, not exported TypeScript or an EvidencePack extension. `Ref` and `Text` are nonempty strings; `Time` is a parseable timestamp with Z or explicit offset. Preserve originals byte-for-byte as strings; reject whitespace-only values, never trim into a different identity. Field order has no semantic effect.

Input keys: `contract_version: "t2-01-private-event-result/0.1"`, `requested_dimension: "occurrence" | "occurrence_and_result"`, `target: {subject: Text, revision: Text, scope: Text}`, optional `occurrence_ref: Ref`, optional `result_refs: Ref[]`, `records: Record<Ref, JsonValue>`. Absence of result_refs differs from an explicitly supplied empty set; retain both. Target errors are input diagnostics, not invented event facts. Unknown raw record content is retained. Unknown contract/control keys are rejected.

Records have the following exact interpreted fields; each may be absent, null or malformed in raw input. The listed types are satisfaction requirements, not permission for a parser to drop incomplete evidence:

| Record kind | Fields required for the named satisfied basis |
|---|---|
| `verification_occurrence` | `kind`, `source_namespace: Text`, `source_ref: Ref`, `event_id: Text`, `subject: Text`, `revision: Text`, `scope: Text`, `checked_property: Text`, `method: Text`, `method_version: Text`, `event_time: Time`, `producer: Text`, `verifier: Text`, `output_refs: Ref[]` (nonempty) |
| `verification_result` | all occurrence fields except `kind` is verification_result and output_refs is replaced by `output_ref: Ref`, plus `event_ref: Ref`, `input_ref: Ref`, `criterion: Text`, `result: "passed" | "failed" | "inconclusive"`, `limitations: Text` |
| `input` | `kind`, `source_namespace: Text`, `source_ref: Ref`, `subject: Text`, `revision: Text`, `scope: Text`, `content: JsonValue` explicitly supplied |
| `output` | `kind`, `source_namespace: Text`, `source_ref: Ref`, `event_id: Text`, `subject: Text`, `revision: Text`, `scope: Text`, `checked_property: Text`, `method: Text`, `method_version: Text`, `event_time: Time`, `content: JsonValue`; result evaluation additionally requires `input_ref: Ref`, `criterion: Text`, `result` in the same three-value set, `limitations: Text` |

Each map key must equal the record's source_ref. References resolve only in the supplied records map: no filesystem, network, Harness or execution lookup. Event/output namespaces and event fields must agree exactly; result also agrees with event attribution, output/result fields and input context, and its output_ref must belong to occurrence.output_refs. Several outputs allow competing result witnesses to survive without overwriting one another. A different namespace requires an explicitly admitted future mapping; none is inferred here. Native event identity is the pair (source_namespace, event_id). A reference label alone with no retained record is missing evidence. Conflicting duplicate keys must be rejected before parsing can erase them; repeated event IDs with incompatible context are retained as conflicts, never overwritten.

Output keys: `contract_version` (same literal), `raw_input: JsonValue` (lossless input copy), `annotation` (one of the four below, omitted for invalid envelope/target), `occurrence_basis: {established: boolean, refs: Ref[]}`, `result_basis: {requested: boolean, established: boolean, refs: Ref[], values: string[]}`, `missing_facts: {path: string, obligation: string}[]`, `diagnostics: {path: string, issue: string, refs: Ref[]}[]`, `provenance: {field: string, record_ref: Ref, pointer: string}[]`. Limitation values remain verbatim in raw result records and their provenance pointers. Output booleans and annotations describe predicate findings; they are not generated factual inputs. Diagnostic strings are private, never public reason codes.

| Annotation | Exact condition |
|---|---|
| NO_ATTRIBUTABLE_OCCURRENCE | Valid target but occurrence basis incomplete, wrong kind, unresolvable or mismatched; does not deny real-world occurrence |
| ATTRIBUTABLE_OCCURRENCE | Full event_basis established and requested_dimension is occurrence; result_basis.requested is false; no result conclusion |
| ATTRIBUTABLE_OCCURRENCE_WITH_RESULT | Full event_basis, a nonempty selected result set, and every selected result_basis valid; no unresolved selected association; all results for this event/property/criterion agree; retain all refs and exact result, including inconclusive |
| ATTRIBUTABLE_OCCURRENCE_RESULT_UNRESOLVED | Full event_basis, result requested, but missing/invalid/ambiguous/conflicting result basis; retain candidate results and exact diagnostics |

Conflicting results are unresolved only as a *single side-result selection*: the output retains both. This annotation never replaces T1 CONFLICTED or relabels conflict as missing evidence. Incompatible criterion/input/method assertions are ambiguity, not automatically same-predicate conflict. Absent, null, empty, wrong-type and mismatched fields retain distinct diagnostics. No generated event ID, clock, checker, criterion, result, method, limitation or synthetic witness fills any gap. `not_run`, skipped rows and arbitrary statuses remain raw assertions and cannot satisfy occurrence by themselves.

## Existing T1 routing, without semantic edits

Future private functions may inspect the side input alone, or bridge it to an independently supplied T1 claim input/coreInput/trust. No public export or default caller is added. Side output contains no `state`; if requested, the wrapper returns the unmodified `evaluateClaims` response separately as `claim_evaluation`.

For a complete bound result, copy only explicit values: event_id -> event_id; subject/scope unchanged; event_time -> event.time and source.event_time; checked_property -> event.property; method/version -> event.method/method_version; producer/verifier unchanged; criterion/result/input_ref/output_ref unchanged; kind becomes the structural literal verification. Copy retained input/output records to evidence_ledger with time=their explicit event_time where present. Never use evaluation_time for that value. Do not infer an input event time where none is required or supplied. Populate V bindings from corresponding explicit values or their explicitly supplied retained references as described below, including verified_at=event_time; preserve limitations verbatim in their source records. Preserve all candidates for a conflict; no last-write merge or selected passing result.

The caller must separately supply canonical requests, admitted registry/lock/trust, explicit evaluation_time and method descriptor id/version/digest. These are semantic evaluation context, not occurrence facts. Require descriptor id/version to match the recorded method/version. Scalar bindings result/limitations may be explicit references to retained result/limitation records, consistent with the collector's nonempty_reference predicate; a multi-result call requires a caller-supplied retained set record containing every candidate reference. Never choose a passing scalar result or concatenate invented limitations to hide a conflict. If such context is absent, withhold claim_evaluation and record its missing context, while preserving the independently evaluated side annotation. This is not UNRESOLVED being fabricated by the wrapper.

Where a valid T1 envelope can be formed, use existing `RequirementContext` with a private binding `t2_01_result_basis` and existing predicate `true`, scoped by exact request path/subject/scope/evaluation_time and source_ref to this contract. The new module computes that boolean from the above result predicates, not caller hints. It is a conjunctive extra requirement, never a replacement for Core. Preserve caller-added obligations. Reject caller collision with this reserved binding. For comparable conflict candidates the gate means that *each competing record is individually admissible*, so it remains true; forward both and let T1 select CONFLICTED. Do not require a unique winner to erase conflict evidence.

For occurrence without a full result, preserve the occurrence annotation. If the caller requests the existing stronger facet, the bridge omits unavailable result bindings and supplies no fabricated complete event; the extra gate is false. Existing T1 yields its own result from its unchanged precedence. A malformed T1 envelope stays REJECTED; no wrapper-made state disguises rejection. Independent complete evidence paths are evaluated separately, not globally vetoed by this path's missing facts.

For complete failed results, the side result is failed; the existing pass claim may be UNSUPPORTED under its criterion, while its occurrence claim may be SUPPORTED only after all T1 obligations. Complete inconclusive results remain present results; the pass claim may be INCONCLUSIVE. These are conditional existing T1 behaviors, not direct status mappings or this dossier's executed outputs.

T1-03 alone selects prohibition -> comparable conflict -> established stale basis -> missing obligation -> completed determination. No new generic basis injection, selector export or modification is needed. T1-04 Core noninterference/admission remains mandatory; side facts cannot replace module admission or widen Core supports. Integrity, independence, custody, authority, acceptance, compliance, current standing and sufficiency are not output claims of this module. T2-02/T2-03/G03 remain deferred. Public migration and authority expansion are NO.
